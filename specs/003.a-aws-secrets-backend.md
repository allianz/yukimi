# Specification: AWS Secrets Backend (003.a)

## Overview

`internal/secrets/aws/` is the concrete implementation of the platform's secret-storage interface that talks to a real cloud secret store. It solves the last mile of the secrets design: without it, the platform can generate and validate credentials but has nowhere real to put them, so no account can actually be created. It exists because every other package in the provider needs to read and write tenant and organization credentials without knowing or caring which vendor holds them, and this is the piece that makes that promise true for one specific vendor, chosen as the platform's reference store. The technical approach is deliberately small: four methods, each translating directly into one call to Amazon's secret-storage service, plus a constructor that wires up the vendor's client library from a region and an optional encryption key.

## Scope

This specification defines the `internal/secrets/aws/` package that:
- Implements the `Backend` interface (003) against AWS Secrets Manager — `Get`, `Create`, `Update`, `Delete` — each a single AWS API call.
- Constructs the AWS Secrets Manager client from a region and an optional KMS key id, using the AWS SDK's default credential chain.
- Wraps every failing AWS call in a plainly worded error naming the operation and the path, preserving the underlying AWS error via `%w` so 001's incident correlation still surfaces it.

**Out of Scope**:
- Path construction, caching, keypair generation, or the credential's own JSON encoding — all owned by 003; this package only decides how the opaque string it is handed gets persisted.
- Any user/system error classification beyond the constructor's empty-region check — 003 already classifies every store fault as a system error, and this package introduces no classification decision of its own.
- Soft-delete recovery, restore, or purge semantics — 003 no longer asks any backend for these and this one does not reintroduce them.
- Any other backend (a Vault-style `003.b` is deliberately unplanned) and backend *selection* — that is `cmd/provider/main.go`'s job.
- IAM policy or grants for the controller's role — ops owns those; no code in this package reads or authors a policy.
- Ops-defined tags on `CreateSecret` — no tags are set in this version (see Edge Cases).

## Key Concept: One Call Per Method, No Error Inspection

Each of `Backend`'s four methods is exactly one AWS call: `Get`→`GetSecretValue`, `Create`→`CreateSecret`, `Update`→`PutSecretValue`, `Delete`→`DeleteSecret`. `Create` never becomes `PutSecretValue` and `Update` never becomes `CreateSecret` — keeping the two distinct is what makes 003's create-if-absent atomic natively in AWS, with no read-then-write in this package. `Delete` leaves AWS's default recovery window in place; there is no `RestoreSecret` or force-delete outside integration-test cleanup.

No call is ever inspected for its AWS error code: 003 defines no sentinel error and no caller branches on identity, and `CreateSecret`/`GetSecretValue`/`PutSecretValue` already fail exactly under the conditions 003's contract requires. Every failure is wrapped with the operation and path and returned as-is (see Error Classification).

`New(region, kmsKeyId string) (secrets.Backend, error)` only validates that `region` is non-empty — a user error otherwise, and the *only* classification decision this package makes anywhere. It makes no AWS call: a bad region or bad credentials surfaces on the first real method call, not at construction. `kmsKeyId`, when non-empty, is stored and passed to every `Create`'s `KmsKeyId`. Credentials come from the AWS SDK's default chain only (IRSA in-cluster, `AWS_PROFILE` locally), unconfigured beyond region.

## Public API

```go
package secretsaws

import (
    "context"

    "github.com/allianz/yukimi/internal/secrets"
)

// Backend implements secrets.Backend (003) against AWS Secrets Manager.
// Each method is exactly one AWS API call; the struct holds only the client
// and the KMS key id carried through to every Create.
type Backend struct { /* unexported */ }

// New constructs a Backend for region. It loads credentials from the AWS
// SDK's default chain only and makes no AWS API call — a bad region or bad
// credentials surfaces on the first real Get/Create/Update/Delete, not here.
//
// Parameters:
//   - region: AWS region secrets are stored in (BaseConfig.AWS.Region, 002)
//   - kmsKeyId: optional customer-managed KMS key id, alias, or ARN
//     (BaseConfig.AWS.KmsKeyId, 002); passed to CreateSecret's KmsKeyId only
//     when non-empty — otherwise Secrets Manager's AWS-managed default key
//     encrypts the secret
//
// Returns:
//   - secrets.Backend: never nil on a nil error
//   - User error if region is empty
//   - System error if the AWS SDK's own local config/credential loading
//     fails (e.g. a malformed shared config file) — this is not a network
//     call and not specific to Secrets Manager
func New(region, kmsKeyId string) (secrets.Backend, error)

// Get reads the value stored at path via GetSecretValue.
//
// Returns:
//   - System error if the secret does not exist or the call otherwise fails
func (b *Backend) Get(ctx context.Context, path secrets.Path) (string, error)

// Create stores value at path via CreateSecret, setting KmsKeyId when the
// constructor was given one. Never calls PutSecretValue.
//
// Returns:
//   - System error if path is already occupied or the call otherwise fails
func (b *Backend) Create(ctx context.Context, path secrets.Path, value string) error

// Update overwrites the value at path via PutSecretValue. Never calls
// CreateSecret.
//
// Returns:
//   - System error if nothing is stored at path or the call otherwise fails
func (b *Backend) Update(ctx context.Context, path secrets.Path, value string) error

// Delete removes path via DeleteSecret, leaving AWS's default recovery
// window in place. Never calls RestoreSecret or ForceDeleteWithoutRecovery.
//
// Returns:
//   - System error if the call fails, including on an already-absent path
//     (AWS's ResourceNotFoundException) — unlike 003's FakeBackend.Delete,
//     this is not idempotent (see Edge Cases)
func (b *Backend) Delete(ctx context.Context, path secrets.Path) error
```

No `types.go`/`_impl.go`: the `Backend` struct, the small `client` interface it is constructed over (satisfied unchanged by the real `*secretsmanager.Client`, and by a fake in `backend_test.go`), and all four method bodies live together in `backend.go`, per this repo's conventions.

## Error Classification

**User Errors** (use `errors.NewUserError()`):
- Empty region at construction: `AWS region is required to construct the secrets backend (expected: aws.region in baseConfig.yaml)`

This is the only user error this package produces. Every other failure it can produce is a system error, full stop — there is no second classification decision anywhere in `Get`, `Create`, `Update`, or `Delete`.

**System Errors** (use `fmt.Errorf("context: %w", err)`):
- `GetSecretValue` on a missing or unreadable secret: `failed to get secret at snowflake/tenant/my_org/finance/analytics-team-eu/platform-credentials: %w`
- `CreateSecret` on an occupied name, or any other create fault: `failed to create secret at snowflake/org/my_org/platform/org-admin-credentials: %w`
- `PutSecretValue` on a missing secret, or any other update fault: `failed to update secret at snowflake/tenant/my_org/finance/analytics-team-eu/platform-credentials: %w`
- `DeleteSecret` failure, including on an already-absent secret: `failed to delete secret at snowflake/tenant/my_org/finance/analytics-team-eu/platform-credentials: %w`
- AWS SDK local config/credential loading failure at construction (after the region check passes): `failed to load AWS SDK config: %w`

## Edge Cases

- **Why doesn't any method match a specific AWS error code?** - Because 003 defines no sentinel error and no caller branches on identity. `CreateSecret` already fails exactly when a path is occupied, and `GetSecretValue`/`PutSecretValue` already fail exactly when nothing is stored — the AWS API's own success/failure conditions are precisely 003's per-method contract, so there is nothing left for this package to detect.
- **`Delete` on an already-absent path: idempotent or not?** - Not idempotent, unlike 003's `FakeBackend.Delete`. AWS's real `DeleteSecret` on a nonexistent name returns `ResourceNotFoundException`, and per the error-reporting rule above this package wraps and returns it like any other fault rather than swallowing it. This is a real, intentional behavioral difference between the fake and this backend — not a bug to reconcile.
- **`CreateSecret` onto a path whose predecessor is still inside AWS's recovery window** - Fails and is reported like any other AWS fault. This is what 003 calls "clearing a genuinely stale path" — an operator action outside this package, not something it detects or resolves. An account deleted and recreated under the same `metadata.name` within the window needs that operator step.
- **What if `kmsKeyId` is empty?** - `CreateSecret`'s `KmsKeyId` field is left unset entirely (never sent as an empty string), so Secrets Manager falls back to its AWS-managed default encryption key. `Get`, `Update`, and `Delete` never reference a KMS key at all.
- **Does this package validate that `region` names a real AWS region, or that credentials are valid?** - No. Both surface as an ordinary system error on the first real API call the constructed `Backend` makes — the constructor performs no such check, deliberately, so a bad region is indistinguishable at construction time from a good one (Key Concept: One Call Per Method, No Error Inspection).
- **Should `CreateSecret` carry ops-defined tags?** - Not in this version. No tags are set. This is recorded as an explicit open item rather than solved here: if ops later needs tags for cost attribution, they arrive as another passed-through, uninterpreted `AWSSettings` field, exactly like `kmsKeyId` is today — never something this package invents a policy around.
- **What happens to the value stored when the string is empty (`""`)?** - Nothing special. This package draws no distinction based on the string's contents; an empty value is carried into `SecretString` exactly like any other string, and AWS's own acceptance or rejection of it is reported like any other fault.

## Dependencies

- **`internal/secrets` (003)** - Used APIs: `secrets.Backend`, `secrets.Path` - Contract: this package implements `Backend` faithfully against its per-method contract and never imports `internal/secrets/aws` back (that direction is a compile error, since 003 owns the interface `Backend` type this package returns).
- **`internal/errors` (001)** - Used APIs: `errors.NewUserError()` - Contract: used exactly once, for `New`'s empty-region check; nowhere else in this package.
- **`aws-sdk-go-v2`** (`config`, `service/secretsmanager`) - the only spec in the tree that adds an AWS dependency to `go.mod`.

## Integration Points

- **`cmd/provider/main.go`** - Constructs the backend via `secretsaws.New(cfg.AWS.Region, cfg.AWS.KmsKeyId)` inside the `switch cfg.CloudProvider() { case "aws": ... }` branch 002 anticipates, then wraps the result exactly once in `secrets.NewCachedBackend(...)` before handing it to every consumer (004, 010, etc.) - Key functions: `secretsaws.New()`, `secrets.NewCachedBackend()` - Notes: this is the *only* file in the tree allowed to import `internal/secrets/aws`; an import of this package anywhere outside `cmd/provider/` is a bug, and that single grep is what proves the store stays pluggable.
- **`internal/secrets` (003)** - Owns the interface this package implements and the `Path` type this package's methods receive - Key functions: `secrets.Backend`, `Path.String()` - Notes: the dependency is one-way; 003 never imports this package.
- **Ops / IAM** - The controller's role needs IAM permissions for `GetSecretValue`/`CreateSecret`/`PutSecretValue`/`DeleteSecret` scoped to the path grammar (design.md 3.11.1) - Notes: authoring and granting that policy is entirely ops's responsibility; no code in this package reads or authors one.

## Success Criteria

- **SC-001**: `Get` calls `GetSecretValue` and only `GetSecretValue`, reading the value back from `SecretString`.
- **SC-002**: `Create` calls `CreateSecret` and only `CreateSecret`, carrying `value` in `SecretString` and never in `SecretBinary`.
- **SC-003**: `Create` sets `CreateSecretInput.KmsKeyId` only when the constructor was given a non-empty `kmsKeyId`; it is left unset otherwise.
- **SC-004**: `Update` calls `PutSecretValue` and never `CreateSecret`.
- **SC-005**: `Delete` calls `DeleteSecret` and never `RestoreSecret` or `ForceDeleteWithoutRecovery`, except in `integration_test.go`'s own cleanup code.
- **SC-006**: `New` returns a user error when `region` is empty; for any non-empty region it returns a non-nil `Backend` and makes zero AWS API calls, unless the AWS SDK's own local config loading fails, which surfaces as a system error instead.
- **SC-007**: Every failing AWS call returns an error wrapped with the operation and the path (`failed to <verb> secret at <path>: %w`), and `errors.Unwrap`/`errors.As` still reaches the original AWS error through the chain.
- **SC-008**: No code in this package inspects, switches on, or matches an AWS error code or type — grep-provable by the absence of any `errors.As` against an AWS/smithy error type or any check of an AWS exception's name.
- **SC-009**: This package imports only `internal/secrets`, `internal/errors`, and the AWS SDK among dependencies with an `internal/` or vendor boundary — no other package internal to this repository.
- **SC-010**: No package outside `cmd/provider/` imports `internal/secrets/aws` — grep-provable.
- **SC-011**: `*Backend` satisfies `secrets.Backend` at compile time.
- **SC-012**: Unit tests run entirely against a fake implementing the four AWS calls this package uses — no real AWS account, no network call, in `backend_test.go`.
- **SC-013**: Unit tests cover, for each of the four methods, both a success path (verifying the correct API call and parameters) and a failure path (verifying the wrapped-error format).
- **SC-014**: Unit test coverage exceeds 95%.
- **SC-015**: Integration tests are named `TestIntegration...`, run only via `make test-integration`, and are skipped when tests run with `-short`.
- **SC-016**: Integration tests read exactly `AWS_REGION`, `AWS_PROFILE`, `SAMPLE_CUSTOMER_NAMESPACE`, and `SAMPLE_CUSTOMER_ACCOUNT` from the environment (via `.env`), and construct their test path with `secrets.NewTenantPath` from the latter two.
- **SC-017**: Integration test cleanup is the only code path anywhere in this package that calls `ForceDeleteWithoutRecovery`, allowing the same test path to be reused across consecutive runs.
- **SC-018**: No credential value (secret string content) ever appears in an error message this package produces — only a path, an operation name, and the underlying AWS error.

## Security Considerations

- **`Path.String()` as the AWS secret name**: this package sends `path.String()` verbatim as `Name`/`SecretId` on every call. Real tenant-isolation enforcement is AWS IAM's resource and identity policies evaluating that name — this package's own contribution is limited to never inventing a name outside what `Path` already validated (003, §Security Considerations).
- **IAM policy authorship is out of scope**: this package neither reads nor authors any IAM policy; scoping the controller's role to the path grammar (design.md 3.11.1) is entirely ops's job.
- **No credential value in error messages**: every wrapped error this package produces is built from a path, a fixed operation verb, and the underlying AWS error — never from the secret string itself.
- **`Create`'s atomicity is native, not emulated**: this package never performs a read before a write. `CreateSecret`'s own create-if-absent semantics are what 003 requires as the sole guard against a retried request overwriting a live credential (003, §Security Considerations); this package adds nothing on top and could not safely emulate it with `GetSecretValue` + `PutSecretValue` without reintroducing a race.
- **Encryption defaults to AWS-managed**: secrets are encrypted with Secrets Manager's default AWS-managed key unless `kmsKeyId` is set. This package neither manages nor validates the referenced key's policy — a KMS key without the controller's role granted `kms:Decrypt`/`kms:GenerateDataKey` fails the same way any other AWS fault does, as an ordinary wrapped system error.

## Appendix: Usage Examples

### Example 1: Wiring the Backend in `cmd/provider/main.go` (Primary Use Case)

```go
import (
    "log"
    "time"

    "github.com/allianz/yukimi/internal/config"
    "github.com/allianz/yukimi/internal/secrets"
    secretsaws "github.com/allianz/yukimi/internal/secrets/aws"
)

func buildSecretsBackend(cfg *config.BaseConfig) secrets.Backend {
    var backend secrets.Backend
    var err error

    switch cfg.CloudProvider() {
    case "aws":
        backend, err = secretsaws.New(cfg.AWS.Region, cfg.AWS.KmsKeyId)
        if err != nil {
            log.Fatalf("failed to construct AWS secrets backend: %v", err)
        }
    default:
        log.Fatalf("no secrets backend compiled in for cloud section %q (compiled in: aws)", cfg.CloudProvider())
    }

    // Wrapped exactly once, here — every consumer below (004, 010, ...)
    // depends only on secrets.Backend and never imports secretsaws directly.
    return secrets.NewCachedBackend(backend, 5*time.Minute)
}
```

### Example 2: Unit Testing `Create` Against a Fake `secretsmanager` Client

```go
package secretsaws

import (
    "context"
    "errors"
    "testing"

    "github.com/aws/aws-sdk-go-v2/aws"
    "github.com/aws/aws-sdk-go-v2/service/secretsmanager"

    "github.com/allianz/yukimi/internal/secrets"
)

// fakeClient implements this package's client interface with no AWS account
// and no network. occupied simulates AWS's own response to an occupied name.
type fakeClient struct {
    occupied         bool
    putSecretCalled  bool
    createSecretCall *secretsmanager.CreateSecretInput
}

func (f *fakeClient) CreateSecret(_ context.Context, in *secretsmanager.CreateSecretInput, _ ...func(*secretsmanager.Options)) (*secretsmanager.CreateSecretOutput, error) {
    f.createSecretCall = in
    if f.occupied {
        return nil, errors.New("ResourceExistsException: a secret with this name already exists")
    }
    return &secretsmanager.CreateSecretOutput{}, nil
}

func (f *fakeClient) PutSecretValue(context.Context, *secretsmanager.PutSecretValueInput, ...func(*secretsmanager.Options)) (*secretsmanager.PutSecretValueOutput, error) {
    f.putSecretCalled = true
    return &secretsmanager.PutSecretValueOutput{}, nil
}

func (f *fakeClient) GetSecretValue(context.Context, *secretsmanager.GetSecretValueInput, ...func(*secretsmanager.Options)) (*secretsmanager.GetSecretValueOutput, error) {
    return nil, errors.New("not used in this test")
}

func (f *fakeClient) DeleteSecret(context.Context, *secretsmanager.DeleteSecretInput, ...func(*secretsmanager.Options)) (*secretsmanager.DeleteSecretOutput, error) {
    return nil, errors.New("not used in this test")
}

func TestCreate_MapsToCreateSecretAndNeverOverwrites(t *testing.T) {
    ctx := context.Background()
    path, _ := secrets.NewTenantPath("my_org", "finance", "analytics-team-eu")

    fake := &fakeClient{occupied: true}
    backend := &Backend{client: fake, kmsKeyId: "alias/yukimi-secrets"}

    err := backend.Create(ctx, path, "some-opaque-value")
    if err == nil {
        t.Fatal("expected Create to fail on an occupied name")
    }
    if fake.putSecretCalled {
        t.Fatal("Create must never call PutSecretValue")
    }
    if got := aws.ToString(fake.createSecretCall.KmsKeyId); got != "alias/yukimi-secrets" {
        t.Fatalf("KmsKeyId = %q, want the configured key", got)
    }
}
```

### Example 3: Integration Test Skeleton (Gated Behind `make test-integration`)

```go
package secretsaws

import (
    "context"
    "os"
    "testing"

    "github.com/allianz/yukimi/internal/secrets"
)

// TestIntegration_CreateGetDelete only runs via `make test-integration`
// (skipped whenever tests run with -short). It exercises a real AWS Secrets
// Manager call for each of the four methods.
func TestIntegration_CreateGetDelete(t *testing.T) {
    if testing.Short() {
        t.Skip("integration test — run via `make test-integration`")
    }

    ctx := context.Background()
    backend, err := New(os.Getenv("AWS_REGION"), "")
    if err != nil {
        t.Fatalf("New: %v", err)
    }

    // Uses the sample-customer identifiers .env defines, so the path matches
    // the tenant grammar exactly as a real controller would build it.
    path, err := secrets.NewTenantPath(
        "integration-test-prefix",
        os.Getenv("SAMPLE_CUSTOMER_NAMESPACE"),
        os.Getenv("SAMPLE_CUSTOMER_ACCOUNT"),
    )
    if err != nil {
        t.Fatalf("NewTenantPath: %v", err)
    }

    // Cleanup — and only cleanup — uses ForceDeleteWithoutRecovery, so the
    // same path is reusable on the very next run despite Delete's recovery
    // window.
    t.Cleanup(func() { forceDeleteForTest(ctx, t, backend, path) })

    if err := backend.Create(ctx, path, "integration-test-value"); err != nil {
        t.Fatalf("Create: %v", err)
    }
    got, err := backend.Get(ctx, path)
    if err != nil {
        t.Fatalf("Get: %v", err)
    }
    if got != "integration-test-value" {
        t.Fatalf("Get returned %q", got)
    }
    if err := backend.Delete(ctx, path); err != nil {
        t.Fatalf("Delete: %v", err)
    }
}
```
